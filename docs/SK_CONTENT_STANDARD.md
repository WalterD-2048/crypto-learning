# SK 内容标准

> 范围：SK-001 ~ SK-057 的学习内容。本文是备课/审阅标准，不是工程 schema。
> 目标：每个技能点都能回答“学什么、为什么学、怎么练、错了怎么补、何时算掌握”。

---

## 每个 SK 必须具备

1. **学习目标**：一句话说明要形成的可观察能力。
2. **学习理由**：说明该能力如何服务加密货币基础、宏观/周期、风险控制、链上分析、执行、案例或调研能力。
3. **前置技能**：沿用 `teacher/skill_graph.md`，不得破坏现有状态字段格式。
4. **开场 anchor**：至少一个 case dossier、仓库内 guide、题库、模板，或按标题引用的 local-only source。
5. **练习入口**：题库题号、共享题库或模板任务。
6. **评分要点**：能判断答案是否达到 8/10 或模板评审通过。
7. **常见错因**：至少能归到 `概念混淆 / 应用偏差 / 边界遗漏 / 推导断链 / 结果倒推 / 计算错误 / 基础记忆缺失 / 批判不足` 之一。
8. **补救方向**：错因要对应一个具体训练动作。
9. **边界/反例**：每个技能都要能说出这个规则何时失效、变弱或需要别的框架。

## 阶段侧重点

| 阶段 | 能力重点 | 内容最低要求 |
|------|----------|--------------|
| SK-001 ~ SK-018 | 货币理论、比特币机制、宏观周期 | 每题先解释机制，再说明边界；不得把长期叙事写成买卖建议。 |
| SK-019 ~ SK-030 | 概率、风险、仓位、托管、OpSec、日志 | 每题必须落到风险金额、执行边界、攻击路径或复盘字段。 |
| SK-031 ~ SK-042 | 链上数据解读 | 必须区分指标定义、读数含义、适用 regime 和数据失真来源。 |
| SK-043 ~ SK-052 | 工具选择、市场结构、执行、三框架 | 必须把信号转为触发、失效、仓位、订单类型和复盘字段。 |
| SK-053 ~ SK-056 | 重大案例复盘 | 必须锁定当时信息集，避免用结果倒推判断质量。 |
| SK-057 | 毕业策略文档 | 必须有入场、出场、仓位、风险上限、周期框架、样例和失败复盘。 |

## 题库质量要求

一个合格题库至少包含：

- `核心理解`：定义、公式、机制或关系图。
- `概念辨析`：为什么不是相邻概念。
- `场景应用`：放进加密货币/交易场景。
- `边界/反例`：什么时候不能这样用。
- `评分 rubric`：说明满分、部分得分、不通过。
- `错因与补救方向`：错因必须对应可执行补救动作。

共享题库可以覆盖多个 SK，但必须有每个 SK 的错因/补救条目，避免只覆盖其中一个重点技能。

## 发布边界

- 允许引用仓库内自写 guide、case dossier、question bank、template。
- local-only 第三方材料只按标题或来源名引用，例如 `《Broken Money》`、`ARK Invest Bitcoin research report`。
- 不引用 ignored raw-import 路径，不发布书籍、文章、报告原文。
- 所有研究和交易相关内容只训练判断框架，不写直接买/卖/持有建议。
