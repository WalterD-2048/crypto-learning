# 系统重构提案（system_rebuild_proposal.md）

---

## 目的

本提案不讨论“这个系统有没有纪律”，而讨论“它能不能更高效地形成、保持、迁移技能”。

当前系统最大的优点是：
- 概念课和练习课严格分离
- 案例优先，强调推理链和边界条件
- 有技能图谱、练习日志、会话存档三层记录

当前系统最大的短板是：
- 过度强调纪律感，弱化了诊断效率
- “掌握”语义混杂，长期统计失真
- 复习规则机械，容易积累复习债
- 学习者画像没有真正进入教学回路
- 资源结构偏“比特币货币学”，与“加密交易能力”目标不完全匹配

因此，下一阶段目标不是继续加规则，而是把系统改造成：

1. 更强的诊断系统
2. 更清晰的掌握定义
3. 更自适应的复习系统
4. 更闭环的学习者模型
5. 更贴近真实交易能力的课程结构

---

## 当前问题诊断

### 1. 教学风格过硬，但纠错效率不够高

系统现在非常强调：
- 概念课不做先验铺垫，先暴露认知起点
- 复述必须压缩到 3 句话
- 练习课反馈只允许极简格式

这种设计能防止“被带着走”，但会带来另一个问题：
当学习者连续犯同一类错时，系统能记录问题，却不能快速修正问题。

当前日志已经显示出稳定重复的错误模式，例如：
- 边界识别
- 属性混淆
- 批判性判断
- 框架纪律

这些错误不应只体现在“薄弱点”字段里，而应直接改变下一轮教学策略。

### 2. “掌握”语义混在一起

当前系统把以下几种情况都揉进了“掌握”：
- 第一次达标
- 当天重修后再次达标
- 间隔复习通过
- 长期保持

这会造成三个问题：
- `掌握日期` 无法表达“首次掌握”和“最近一次重新掌握”的区别
- 里程碑统计与当前技能状态容易出现双重口径
- 复习时间表会混淆“第一次学会”和“最近一次恢复状态”

### 3. 复习机制过于机械

当前采用固定时间表：
- 7 天
- 21 天
- 60 天
- 90 天

这个框架本身没有问题，问题在于它没有处理“复习债”：
- 当到期技能点累积时，系统只是列出队列
- 没有冻结新课的规则
- 没有根据过期程度和错误类型调整题量和优先级

结果会是：系统越跑越多，复习越欠越多，学习节奏逐渐失真。

### 4. 学习者画像没有进入决策层

`learner_profile.md` 里已经预留了：
- 观察到的倾向
- 常见推理模式
- 需要特别注意的思维陷阱
- 概念课表现记录

但这些信息还没有稳定沉淀，更没有反向影响：
- 下一次概念课如何追问
- 下一次练习课该增加什么题型
- 哪类案例更适合当前学习者

这意味着系统目前还是“记录型系统”，不是“自适应教学系统”。

### 5. 案例优先设计存在 hindsight bias 风险

系统反对“结果倒推”，但又大量依赖历史案例。

如果案例没有明确切分“当时可见的信息”和“事后才知道的结果”，就会出现结构性矛盾：
- 教学目标上反对 hindsight
- 执行方式上却在利用 hindsight

对于交易训练，这是高风险问题。

### 6. 课程结构与目标之间有偏差

当前系统名称是“加密货币交易学习系统”，但课程主线明显偏向：
- 比特币货币属性
- 比特币宏观周期
- 比特币链上数据

这条主线本身没有问题，但如果最终目标是“形成交易决策能力”，还缺少足够强的模块：
- 交易所微观结构
- 衍生品机制
- 稳定币与流动性传导
- 以太坊 / DeFi 风险结构
- 执行层风险和订单层决策

### 7. 当前节奏过慢，系统摩擦偏高

在已有一个多月学习记录的情况下，当前掌握技能点数量仍然很少。

慢不一定是问题，但“慢且已有复习债”通常意味着：
- 单位时间产出的稳定技能不足
- 当前流程摩擦过高
- 纠错路径过长

---

## 重构原则

### 原则 1：不削弱概念课和练习课的分离

这是当前系统最有价值的部分，应该保留。

### 原则 2：减少“单一掌握标准”的误导

不同技能需要不同的掌握证据：
- 记忆提取
- 框架应用
- 迁移判断
- 延迟回忆
- 间隔保持

不应再尝试用单个 `8/10` 覆盖全部意义。

### 原则 3：从“记录错误”升级为“用错误驱动教学”

错误类型必须反向决定：
- 下一次概念课的追问方式
- 下一次练习课的题型比例
- 下一次案例的难度和信息结构

### 原则 4：把复习视为资源调度问题，而不是日历提醒问题

复习队列不是提醒列表，而是系统的主排程器。

### 原则 5：保留 Markdown 驱动，但逐步提高结构化程度

在现阶段仍然以 Markdown 为主要存储介质，但应逐步把“自由文本字段”改造成可校验的结构字段。

---

## 目标结构

### 一、把学习流程拆成 4 个层次

每个技能点不再只有“概念课 -> 练习课 -> 复习”三步，而是：

1. 概念建立
2. 即时提取
3. 延迟验证
4. 间隔保持

对应目标：

| 层次 | 目标 | 典型失败 |
|------|------|---------|
| 概念建立 | 建立因果框架和边界 | 会复述定义但不懂边界 |
| 即时提取 | 从空白状态独立取回 | 靠引导才能答对 |
| 延迟验证 | 24-72 小时后仍能取回 | 当天会，隔天忘 |
| 间隔保持 | 长期保留并迁移应用 | 记住旧题，不会新题 |

### 二、把“掌握”拆成 4 个维度

建议保留当前顶层状态图标，但新增内部维度：

| 维度 | 含义 |
|------|------|
| `concept_ready` | 概念课是否完成 |
| `retrieval_passed` | 即时练习是否通过 |
| `delayed_passed` | 延迟短测是否通过 |
| `review_stage` | 间隔复习进行到哪一轮 |

对外仍可展示为：
- `🔵` 概念已完成
- `🟡` 学习中
- `✅` 已掌握
- `🔄` 复习到期
- `💚` 长期掌握

但系统内部不再只依赖一个状态字段表达全部语义。

### 三、把“首次掌握”和“当前掌握”拆开

建议新增字段：

- `首次掌握日期`
- `最近达标日期`
- `最近复习通过日期`
- `最近复习结果`

规则：
- 里程碑统计使用 `首次掌握日期`
- 当前复习和状态调度使用 `最近达标日期` / `最近复习通过日期`
- 不再让 `掌握日期` 一字段承担两种职责

### 四、把复习从固定日历改成“债务优先 + 自适应”

新增规则：

1. `今日复习到期 >= 3` 时，默认冻结新课
2. `今日复习到期 >= 5` 时，只允许复习，不允许新概念课
3. 过期越久，优先级越高
4. 最近一次复习失败的技能点，优先级高于新到期技能点
5. 同类错误反复出现时，下次复习题型向该错误集中

### 五、让 learner profile 进入教学调度

把稳定错误模式从日志提炼到学习者画像，例如：
- 容易用叙事替代推理
- 记概念定义快，但边界判断弱
- 框架能背出，但中间判断步骤容易跳

然后规定明确映射：

| 画像特征 | 教学动作 |
|---------|---------|
| 边界遗漏高频 | 下次概念课必须加入反例构造 |
| 结果倒推高频 | 案例必须按“当时信息集”呈现 |
| 框架纪律差 | 练习题增加中间步骤显式化要求 |
| 属性混淆高频 | 增加辨析题占比 |

### 六、把案例模板改成“信息切片式”

每个案例应显式分成：
- 当时已知信息
- 当时未知信息
- 学习者当下判断
- 事后结果揭示
- 结果与判断的差异分析

这样才能真正训练决策，而不是训练事后解释。

### 七、把课程结构拆成双主线

建议把整体课程拆成两条主线并行推进：

1. 货币 / 宏观 / 周期主线
2. 风险 / 执行 / 交易结构主线

这样做的原因：
- 宏观框架适合建立方向感
- 风险与执行更应该尽早训练
- 不应等完整学完第一阶段才系统训练交易风险

当前允许 `SK-019` 提前开始是正确方向，应该进一步系统化，而不是只作为一个例外。

## P0 / P1 / P2 优先级

## P0：必须先改

### P0-1. 重定义“掌握”

新增并统一以下口径：
- 首次掌握
- 最近达标
- 延迟验证
- 最近复习通过

这是所有统计和复习逻辑的前提。

### P0-2. 加入延迟验证

即时练习通过后，不直接视为稳定掌握。

建议规则：
- 24-72 小时内增加一次 3-5 题的短测
- 通过后，技能点才进入稳定掌握节奏
- 未通过，则保持 `🟡`

### P0-3. 增加复习债管控

明确冻结规则：
- 到期 3 个以上，默认不进新课
- 到期 5 个以上，只允许做复习

### P0-4. 建立错因 -> 教学动作映射表

错误标签不能只存在日志里。

必须规定：
- 某类错连续出现 2 次时，下次课怎么调整
- 哪些错优先回概念课
- 哪些错优先做变式练习

## P1：第二阶段推进

### P1-1. 改造 learner_profile.md

把它从观察记录改成“教学控制面板”。

至少新增：
- 当前前三大稳定弱点
- 最近两周高频错误
- 概念课推荐追问方式
- 练习课推荐题型偏置

### P1-2. 改造案例模板

所有历史案例改成：
- 信息切片
- 当下判断
- 结果揭示
- 偏差复盘

### P1-3. 课程图谱拆成双主线

将风险/执行主线从“第二阶段以后”前移为并行线。

### P1-4. 把掌握记录升级成能力记录

不仅记录“什么时候掌握”，还记录：
- 通过方式
- 首次达标耗费次数
- 主要失败类型
- 是否经延迟验证

## P2：中长期优化

### P2-1. 扩充资源结构

补齐当前缺口：
- 交易所微观结构
- 衍生品与资金费率深层机制
- 稳定币、流动性与风险传导
- 以太坊 / DeFi 风险结构
- 执行层交易决策

### P2-2. 逐步结构化概念课记录

把概念课日志中的以下部分标准化：
- 案例类型
- 当时信息集
- 学习者初始解释
- Root 追问点
- 盛言指出的断链处
- 最终原则
- 失效边界

### P2-3. 调整节奏目标

系统不仅要追求“严谨”，还要追求“有效进展”。

建议引入运营指标：
- 每周新增稳定掌握技能点数
- 每周消化复习债数量
- 单技能平均达标尝试次数
- 高频错误重复率

---

## 建议的最小落地顺序

### 第 1 步：先改规则，不改大结构

做三件事：
- 定义首次掌握 / 最近达标 / 最近复习通过
- 增加延迟验证
- 增加复习债冻结规则

### 第 2 步：再改画像与案例模板

做两件事：
- 让 learner profile 反向驱动教学
- 把历史案例改成信息切片式

### 第 3 步：最后改课程图谱与资源库

做两件事：
- 双主线重排
- 补充交易执行与结构风险资源

---

## 不建议现在就做的事

- 不建议一次性重写全部技能点描述
- 不建议立刻废弃 Markdown 驱动
- 不建议把系统做成复杂数据库应用
- 不建议增加更多“老师人格规则”，当前问题不在这里

---

## 成功标准

若重构有效，应在 4-8 周内看到以下变化：

1. 复习债不再持续累积
2. 同类错误的重复率明显下降
3. 技能点从“当天过关”到“延迟仍能取回”的比例提高
4. learner profile 中的稳定弱点能持续影响下一轮教学
5. 单位时间内新增稳定掌握技能点数提高

---

## 结论

当前系统的核心价值不在“知识覆盖面”，而在“训练严谨思维”。

下一阶段最该保留的是：
- 案例优先
- 模式隔离
- 推理链审查

最该重构的是：
- 掌握定义
- 复习机制
- 学习者模型
- 案例呈现方式
- 课程主线结构

这份提案的目标不是让系统“更复杂”，而是让它从“严格的老师”升级成“高效的训练系统”。
